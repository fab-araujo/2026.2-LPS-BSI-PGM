## Como usar este repositório

1. **Leia os exemplos aqui mesmo.** Entre na pasta `exemplos/` da aula e clique em qualquer arquivo: o GitHub mostra o código na própria página — sem copiar nada para lugar nenhum. Da aula 3 em diante, cada exemplo também abre no navegador, no GitHub Pages da disciplina; o README da aula dá o endereço. O site que você constrói é o **seu**, no endereço público do GitHub Pages do seu repositório.
2. **Este repositório é material de consulta, não é onde você trabalha** — e é também aqui que você tira dúvida sobre um exemplo. O seu site é escrito no *seu* repositório (`agrofeira-<seu-usuário>`), e é nele que você abre o Codespaces — um codespace pertence a um repositório só.
3. **Pare o codespace ao terminar**, em [github.com/codespaces](https://github.com/codespaces). A cota corre por tempo ligado.

O passo a passo ilustrado está na **apostila de GitHub**, no SIGAA.

## Estrutura

Uma pasta por encontro. Dentro de cada uma:

- `exemplos/` — o que foi mostrado na aula, para você abrir e mexer;
- `inicio/` — quando houver: o material entregue pronto para a atividade, como as imagens da aula 2 e o `reset.css` da aula 3;
- `solucao_atividade_aulaNN/` — ⚠️ a solução da atividade, que só aparece depois do prazo de entrega, com um aviso no topo. Cada atividade parte da anterior: é da solução publicada que continua quem faltou ou empacou.

## O que **não** está aqui

O estado final de cada aula — isto é, a solução da atividade — só é publicado **depois** do prazo de entrega, na pasta `solucao_atividade_aulaNN/` da aula. O que você precisa produzir está descrito no roteiro da atividade, no SIGAA, e o trabalho é seu.
